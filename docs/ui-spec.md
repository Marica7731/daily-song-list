# Daily Song List UI 规范

本规范约束静态站当前 UI。后续 UI 改动应先更新本文件，再同步 `assets/styles.css`、浏览器验证脚本和 README 截图。

## 断点与容器

- 手机：`<= 720px`。首屏优先展示状态、范围切换、搜索入口、筛选状态、摘要、紧凑分页和榜单前几行。
- 平板：`721px - 919px`。采用紧凑榜单列，不套用桌面四列密度。
- 桌面：`>= 920px`。主内容宽度使用 `--page-max`，榜单和工具栏横向对齐。
- 页面横向留白来自 `--page-x` 和 `--content-gutter`。禁止用负 margin 或固定宽度制造横向滚动。

## 设计变量

统一变量集中在 `assets/styles.css` 的 `:root`：

- 背景：`--page-bg`、`--card-bg`
- 文字：`--text-main`、`--text-muted`、`--text-soft`
- 分隔：`--divider`、`--divider-strong`
- 品牌：`--brand`、`--brand-strong`、`--brand-soft`
- 警告：`--warning`、`--warning-soft`
- 间距：`--space-1` 4px、`--space-2` 8px、`--space-3` 12px、`--space-4` 16px、`--space-6` 24px
- 圆角：`--radius-control`、`--radius-panel`、`--radius-pill`
- 阴影：`--shadow-soft`
- 排行右侧列：`--rank-side-width-mobile` 66px、`--rank-side-width-tablet` 76px、`--rank-side-width-desktop` 104px

字体字重只使用 400、500、600、700。不得再引入 750、780、850、900 等不稳定字重。

## 榜单行

- 手机列宽：排名约 36px，内容列自适应，次数/趋势列使用 `--rank-side-width-mobile`。
- 歌曲名是最高层级，15px-16px，最多两行。
- 歌手、来源、频道和趋势是次级信息，使用 12px-13px。
- 次数和趋势固定在右侧 `rank-side`，不得随标题长度移动。
- 整行不可作为 YouTube 大链接；时间戳、频道和视频标题分别是独立链接。
- 趋势标签必须明确对象：名次变化使用 `名次↑N` / `名次↓N`，收录增加使用 `收录+N`，数据修正减少使用 `修正−N`。禁止回退到裸 `升N`、`降N`、`增N`、`减N`。当名次和收录同时变化时，可见标签优先展示收录变化，`title` 和 `aria-label` 补全名次说明。

## 来源披露

歌曲榜和歌曲索引使用同一模型：`FrontendUtils.sourcePresentationModel`。

- 0 个唯一来源视频：内容列显示弱化 `无来源`，没有按钮，没有 drawer。
- 内联来源必须显示微缩视频封面。封面固定 16:9，手机默认 52px × 29px，320px 极窄屏 48px × 27px，平板和桌面 56px × 32px。图片使用 `object-fit: cover`，`loading="lazy"`、`decoding="async"`、`fetchpriority="low"`。
- 内联来源封面不得被时间戳、频道名、状态标签、按钮、渐变文字条或任何覆盖层遮挡。主时间戳显示在频道下方的 `.source-inline-meta` 元信息行，使用小号青绿色 tabular 数字；`38:00`、`2:36:03`、`8:40:21`、`12:34:56` 等长时间必须完整显示。空间不足时优先省略频道名，时间不得被省略或裁切。
- 内联来源内部使用两行正文：第一行频道，第二行时间和额外时间点按钮。封面链接保留鼠标/触控跳转但不增加连续键盘焦点，时间链接承担键盘访问同一时间点。
- 平板和桌面内联来源使用自适应操作轨；1 个、2 个、3+ 来源都必须填满可用预览轨道，不能留下固定第三列空白。手机仍使用单列全宽来源卡片。
- 1 个唯一来源视频：内联显示微缩封面、频道、主时间戳、复制歌单按钮。复制歌单必须基于该来源视频已知的全部时间戳歌曲，不得只复制当前命中的一首。若同一视频有多个时间点，只展开额外时间点，不打开 drawer。
- 2 个唯一来源视频：全部内联显示，不打开 drawer，不显示复制全部链接入口。
- 3 个唯一来源视频：移动端默认内联前 2 个真实来源，通过紧凑 `查看全部来源` 操作进入展开区；平板和桌面 proof fixture 覆盖 3 个来源布局。复制同一首歌全部来源链接仅在展开 toolbar 中出现，避免折叠态动作过多。
- 4 个以上唯一来源视频：移动端默认内联前 2 个，平板和桌面 proof fixture 覆盖 3 个来源布局；紧凑显示 `查看全部来源`，完整语义写入 `title` 和 `aria-label`。点击一次后显示该歌曲全部来源，不再只显示折叠态之外的部分，也不得再出现二次 `查看更多来源`。
- 3+ 折叠态移动端允许 2 个真实内联来源和 1 个紧凑查看全部入口；平板/桌面 3 来源 fixture 使用 `.source-inline-tail`，第三个来源占剩余宽度，`查看全部来源` / `收起来源` 按钮自适应文字且最大宽度约 92px。
- 4+ 折叠态的内联来源必须真实渲染且至少显示非空频道名；不得用 `display:none` 隐藏第 2 个移动来源，或隐藏平板/桌面第 3 个来源、频道名、时间点或复制按钮来伪装压缩。
- 来源预览是 `.rank-row` / `.index-row` 的直接子元素，使用 `grid-area: sources` 横跨序号、内容和右侧列；手机排行网格为 `"rank content side"`、`"sources sources sources"`、`"drawer drawer drawer"`。
- `.source-inline-more` 是 3+ 来源折叠态的查看全部入口；展开后折叠预览条隐藏，drawer 顶部提供 `收起来源`。
- Drawer 用于 3+ 的完整来源列表，宽度必须占满榜单可用宽度，内容高度由实际内容决定。工具栏文案使用 `全部 N 个来源`，右侧保留复制全部链接图标和一个顶部收起按钮；长列表可以保留一个弱化底部 `收起来源`。
- 歌手榜仍保留曲目展开逻辑，不使用歌曲来源内联模型。

## 分页

- `visiblePageTokens` 只返回 `page` 和非交互 `ellipsis`。省略号不可点击，不含跳转目标。
- Web/桌面列表每页 30 个，H5/移动端与平板列表每页 20 个；页面不再暴露每页数量切换。
- 手机顶部普通榜单使用页码输入 stepper：上一页图标、输入页码、`选页`、下一页图标。按钮 28px-30px，间距约 4px，不显示邻页数字或下拉。
- 手机歌曲索引顶部合并为 `index-toolbar`：首字母选择 + 页码输入 + 前后页图标，不显示邻页数字。
- 手机底部保留上一页、页码输入、`选页`、下一页；不显示首页、末页或每页数量控制。
- 桌面/平板底部分页必须提供页码数字输入跳转；输入控件宽度固定，提交后按有效页码夹取，不得撑开或挤歪数字页码区。
- 桌面/平板可继续使用数字页码和非交互省略号。
- 普通榜单默认页大小由 `FrontendUtils.responsiveListPageSize` 统一维护：桌面默认 30 条，手机/平板默认 20 条；显式 URL 只能使用 20 或 30。
- 来源展开抽屉独立分页：桌面每页最多 30 个来源视频，手机/平板每页最多 20 个来源视频；分页必须提供上一页、输入页码、`选页`、下一页，不使用下拉。展开时必须先显示加载/错误状态，不得静默空白；API 模式请求 `/api/sources/{sourceDetailKey}?page=...&pageSize=...`，静态详情 shard 则只渲染当前页作为兼容 fallback。
- VTuber 频道展开的歌曲卡片使用同一套 30/20 分页：桌面每页 30 首，H5/平板每页 20 首。桌面卡片区使用三列密排；H5 使用两列固定等高信息卡，缩略图、歌名、歌手和次数都靠左/靠右规则明确，不得把标题居中或留下序号列下方的空白。
- VTuber 展开卡片发布前可运行 `npm run check:vtuber-expand-layout`：该脚本会用浏览器在 390px、320px 和桌面宽度验证展开卡片数量、列数、长文本不横向溢出、卡片等宽等高，以及翻页/输入页码后缩略图仍显示。

## 查询面板

- 移动端 `queryTrigger` 是固定正方形，只显示一个图标；不得显示没有上下文的数字徽标、圆点或未读提示。存在活动条件时只能使用边框、浅背景和品牌色图标表达状态，语义由按钮 `aria-label` 列出数量和条件。
- `queryDialog` 是唯一搜索与筛选入口。
- 搜索输入固定在面板顶部，始终可见。
- 面板内部不得再拆成 `搜索` / `筛选` 两个 tab。搜索字段、排行条件、显示设置和历史快照必须处于同一个可滚动面板，手机端尤其不能让搜索词和筛选条件分属两个 tab；不要展示匹配建议、猜搜索或最近搜索块。
- 歌曲榜默认搜索字段是 `歌名` 与 `歌手` 两个独立 checkbox，页面进入和刷新时都默认勾选，字段勾选不写入 URL。搜索词只有一个 chip；字段 chip 可单独删除，剩余字段同时参与搜索，字段全删时表示当前请求全字段搜索，包含频道、视频和来源上下文。
- 默认进入页面时显示无歌手收录；`隐藏无歌手` 是正向缩小结果集的筛选条件，只有开启后才显示 chip 和计入条件数量。新 URL 只序列化 `hideUnknown=1`，不再写 `showUnknown`；旧 `showUnknown` 仅作为入站兼容。
- 可删除 chip 只能代表真实缩小结果集的条件：搜索词、搜索字段、只看小众、隐藏无歌手、趋势筛选和最低收录。排行口径、每页数量、历史快照和视频布局不得显示为可删除筛选 chip，也不得计入查询按钮数量。`清除全部` 只清除这些缩小条件，必须保留排行口径、每页数量、当前 range/view、历史快照和视频布局，并把搜索字段恢复为默认 `歌名` + `歌手`。
- 搜索与隐藏无歌手、小众、最低收录、趋势条件必须取交集；开启 `隐藏无歌手` 后，搜索词不得把无歌手结果或只由无歌手歌曲组成的视频重新带回来。
- 歌手榜不受 `隐藏无歌手` 影响；该控制应隐藏或禁用，且不显示 chip、不计入条件数量。
- 历史快照默认折叠，展开后显示日期和时间选择。
- Footer 只有左侧重置和右侧主操作，结果数量写入主按钮文本。
- `active-query-strip` 是移动端解释活动条件的主位置。存在时高度约 26px-28px，chip 高度 24px-26px，单行横向滚动；隐藏时 `display:none`，不得留下空白。每个 chip 自带关闭按钮，只有活动条件数量大于等于 2 时才显示 `清除全部`。
- 移动摘要指标必须是独立 `span` 并通过 CSS `gap` 分隔，不得在文本中插入可能换到行首的中点。搜索/筛选状态也使用自然中文量词，例如 `1首歌曲`、`3歌曲收录`、`3个视频`，不得写成 `1首结果` 或 `3视频`。存在搜索词时，无歌手隐藏提示应压缩为 `已隐藏无歌手`，完整数量只放在 `title` 或查询面板说明。

## 歌曲索引

- 手机端不使用重卡片式索引导航。
- `index-toolbar` 固定在顶部区域下方，合并首字母选择和页码。
- `全部` 桶使用轻量 24px 左右分隔标题；指定桶不重复显示大标题。
- 基础行高约 54px；有内联来源时由内容自然增加，不使用固定高度遮挡。

## 视频页

- 桌面 Web 视频页固定一行 3 个卡片；平板 2 个；手机 1 个。
- 网格卡片必须保持等宽等高的响应式轨道，桌面首屏不得退化成两列。
- 视频标题必须是可点击的 YouTube 链接，缩略图和标题都打开同一个视频。
- 手机视频卡片使用缩略图 + 内容双列，歌单列表占满卡片宽度。手机缩略图保持小封面但不能小到失去识别性，目标宽度约 118px-144px。
- 展开长歌单后顶部和底部都提供收起按钮。

## VTuber 频道

- 频道行优先显示真实频道头像。字段缺失或图片加载失败时使用最新视频封面；只有极端缺图时隐藏图片节点并保留版式空间，不得显示破图或默认无图占位。
- 已进入曲库或来源目录的频道显示 `已收录` tag。tag 必须占用独立网格行，不得和频道名争用同一横向空间；移动端频道名、tag、handle 应从同一内容列左边界开始对齐。
- 排序支持歌唱次数、曲目数、歌枠/视频数量；默认仍是歌唱次数。`metric=songs` 只用于 VTuber 频道页，切到其它榜单时回到已有排序口径。
- 折叠频道行不展示代表歌曲；内容列展示频道 handle，右侧只展示当前排序指标和 `展开` / `收起` 动作。歌曲数、视频数不在折叠动作按钮中重复外透。
- 曲目展开不得一次性渲染几千首。VTuber 频道展开使用独立分页，桌面每页 30 首，H5/平板每页 20 首；歌曲卡片只显示出现次数最高的第一个已知歌手，日期统一显示 `YYYY-MM-DD`。
- VTuber 频道展开内容是该频道唱过的歌曲列表，不是来源视频卡片列表。歌曲按该频道歌唱次数倒序；行内显示歌名、歌手、该频道唱过次数、来源视频数，并使用该频道最新唱这首歌的视频封面。再展开单首歌时显示该频道唱这首歌的全部时间戳来源，并保留复制时间戳链接列表。
- 代表曲目预览必须过滤明显章节词，例如 `END`、`Opening`、`Ending`、`オープニング`、`エンディング`、`エンドカード`、`セットリスト`、`セトリ`、`タイムスタンプ`。

## 底部导航

- 移动底部导航保留五个完整点击热区，单项有效高度至少 42px。
- 当前项不得给整个四分之一导航单元填满浅绿色；选中背景只包住 `.bottom-nav-icon-wrap`，文字和图标改为品牌色。
- 图标尺寸保持约 20px，导航总高度约 52px 加 `safe-area-inset-bottom`，不得遮挡分页、toast、来源收起或视频收起按钮。

## 数据与 Range 文档

- 当前核心 runtime 生成 `7d` 与 `all`；`72h` 与 `1m` 只作为 legacy alias 兼容旧 URL 和旧文件入口。
- VSinger Moment 等外部来源会话导入只补来源证据，不默认标记为已收录；只有本地基线、人工补录或明确的来源会话收录记录才算已收录。
- 数据架构见 `docs/data-architecture.md`，存储文件职责见 `docs/storage-layout.md`，backfill 语义见 `docs/backfill.md`。
- 分片分页、搜索索引和快照索引 proof 必须来自 `test/fixtures/ui-proof-runtime.json`，不得依赖当前本地 `data/` 文件是否正好包含某个结果。

## 移动垂直预算与强调色
